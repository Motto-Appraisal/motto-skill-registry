
# TrueTracts Appraisal Templates — Memory

## Panning the map (better than zoom-button hunting)
- `left_click_drag` on the map (start/end coords both inside the map area) pans the view without triggering Leaflet zoom. This is more reliable than repeated tiny zoom-button clicks for tracing all four polygon edges — drag toward the direction you want to reveal (e.g. drag left→right to reveal what's to the west).
- Workflow: zoom in once or twice via the on-map "+" button (screenshot after each click), then use left_click_drag to pan and reveal each edge/corner in turn, screenshotting/cropping to read the street label right on the polygon line.
- The gold/black polygon can be a full quadrilateral with slanted (non-orthogonal) edges, e.g. a NW-SE diagonal edge — don't assume edges are perfectly N/S/E/W aligned; identify each edge by the actual line direction and follow it to find the adjacent street label.

## Additional gotchas (session 2)
- "Stories" filter can appear as a single-value range like "Stories: 1-1", meaning only 1-story homes were included. In that case, rewrite the template's "1-2 stories" phrasing as singular "1 story" rather than forcing a range.
- Polygon edges don't always have a street label directly on the line for their entire length. A horizontal/vertical stretch may run through unlabeled backyards while the same edge's diagonal corner segment (often near where it bends toward the next edge) does have a legible label right on the line — use that label for the whole edge rather than concluding the edge is unlabeled. Confirmed working method: zoom in, then use left_click_drag panning (not map zoom buttons) to walk the cursor along the line in small steps, screenshotting/cropping at each bend to catch the label.
- The subject pin ("S" marker) is not always centered in the polygon — it can sit close to one edge (e.g., just above the South edge). Don't use pin position alone to sanity-check which edge you're looking at; re-zoom out to see the whole polygon shape/orientation instead.

## Session 3 notes
- Bathroom $/full-bath and $/half-bath adjustments can be entirely absent from the "Adjustment Analysis" section text (grep for "bath" returned zero hits beyond the filter line) even when Garage Spaces and other feature adjustments ARE present — don't assume bath adjustment absence implies garage is also absent, check each independently.
- "Baths" filter can show as a plain integer range like "Baths: 2 - 3" (no half-bath granularity) even though the base template phrasing assumes X-Y.5 format; just use the range as shown on the page.
- The gold/black polygon can be a 5-6 sided irregular kite/dart shape (not a clean quadrilateral) where one edge bends partway along a single street (the street itself curves/changes name) — this doesn't mean there are extra boundary directions, just trace each of the 4 cardinal edges (which may span 1-2 line segments each) to its own street label. Successfully traced a session where N=Lebanon Rd, W=Main St, E=Morning Star Dr, S=S Colony Blvd this way using left_click_drag panning + zoom-in screenshots per edge.
- When the market's average-adjusted-sale-price trend is reconciled "relatively stable" but a sub-metric like Seller Concession Contribution is separately reconciled "increasing" while the sibling metric (% of sales w/ concessions) is reconciled "relatively stable", the base template's single trailing "reconciled as relatively stable and market-typical" clause covering both doesn't cleanly fit — split the reconciliation phrase per metric rather than forcing one label, and flag this nuance in the output to the user.

## Session-specific gotchas seen so far
- Not every session's "Feature filters applied" list includes all of Baths/Bedrooms/GLA/Lot Size/Stories/Year Built/Garage — some sessions omit Lot Size, Garage, and Year Built filters entirely from search parameters (only Baths, Bedrooms, GLA, Stories, Sold Price shown). Don't assume the template's full filter list has a live counterpart every time; check what's actually on the page and flag omissions.
- Baths/Bedrooms filters have sometimes displayed as small negative-to-positive ranges (e.g. "Baths: -2 - 2", "Bedrooms: -3 - 3") rather than absolute counts like the base template's "3-4 bedrooms, 2-3.5 baths" phrasing. This looks like a relative/delta filter format from Comp Finder rather than an absolute range, and the subject's absolute bed/bath count isn't shown elsewhere on the export page to convert it. When seen, flag to the user rather than guessing a converted absolute range.
- Garage $/space adjustment is frequently absent from the Adjustment Analysis section entirely (not just missing a number) — some sessions have no Garage feature adjustment section at all. Confirmed by scanning the full adjustment section text for "Garage" with no hits.

## Session 5 notes
- Confirmed the "assign edge by orientation" heuristic works well for a clean 4-vertex diamond/kite polygon rotated ~45° from cardinal: compare each edge's dx vs dy (screen-pixel deltas between its two endpoint vertices) — edges where dx>dy (more horizontal) map to North/South, edges where dy>dx (more vertical) map to East/West; then use vertex position relative to polygon centroid to pick which of the pair (e.g. N vs S) it is.
- This session's polygon (Wylie, TX area): North=State Highway 78 (label alternates "N State Hwy 78"/"S State Hwy 78" along its length — used plain "State Highway 78"), East=E Farm to Market Rd 544 (edge starts as "Eubanks Ln" near the N vertex then becomes "E Farm To Market Rd 544"/FM 544 for most of its length — used the FM 544 name as the more prominent arterial), South=Elm Dr, West=Sachse Rd.
- Two separate 12-month market-analysis datasets can appear on one export page: a "market area" one (larger sample, e.g. 422 sales, feeding the main Sale Price Trend/Months Supply/DOM/Ratios/Distressed/Concessions charts used for Template 1's Market Analysis paragraph) and a separate, smaller "subject's neighborhood" 1004MC-page dataset (e.g. 32 sales) with its own concession/distressed figures. Don't mix them up — Template 1 uses the market-area-level figures (the ones tied to the named trend charts: Sale Price Trend, Months of Housing Supply Trend, Marketing Time (DOM) Trend, Sale to Final/Original List Price Ratio Trend, Distressed Sales Trend, Sales with Seller Concessions Trend, Seller Concession Contribution Trend).
- The Page-1 Housing Trends checkboxes (find via `find` tool) are the authoritative source for Template 3's three direction words (Property Values Increasing/Stable/Declining, Demand/Supply Shortage/In Balance/Over Supply, Marketing Time Under 3/3-6/Over 6 months) — this session all three happened to already match the base template's wording exactly (Declining, Shortage, Under 3 months), so Template 3 needed zero edits. Always check even when you expect a match.
- Bathroom $/full and $/half adjustment values matched the base template exactly this session ($11,000/$5,500) — still worth double-checking each run since it coincidentally won't always require an edit.

## Session 4 notes
- "Stories" filter shown as upper-bound-only (e.g. "Stories: ≤ 3") — rephrased template's "1-2 stories" as "up to 3 stories" (matching the garage-spaces "up to N" phrasing pattern) rather than forcing a two-sided range.
- Months of Housing Supply can move in the opposite direction from the base template (increasing into oversupply rather than decreasing into shortage) — the Page-1 Housing Trends checkboxes (Property Values: Increasing/Stable/Declining, Demand/Supply: Shortage/In Balance/Over Supply, Marketing Time: Under 3/3-6/Over 6 months) are the authoritative reconciled labels; find them via `find` tool (checkbox checked=true) rather than inferring from raw numbers alone, since e.g. a +6 day DOM increase doesn't by itself indicate the appraiser's reconciled marketing-time trend bucket.
- Confirmed street-tracing method again: zoom in 1-2 clicks, then left_click_drag panning (click first on a neutral area to clear any text selection before dragging, since a drag starting over a text-containing panel can select page text instead of panning the map) reliably reveals each edge's label. This session's polygon was a clean rectangle: N=Virginia Pkwy, W=Coit Rd, E=N Cotton Ridge Rd (label reads "S Cotton Rdg Rd" further south along the same edge — same street, N/S prefix change), S=Eldorado Pkwy.
- Garage $/space adjustment again absent from Adjustment Analysis text this session (grep for "garage" only matched the filter line) — third session in a row where this has happened; likely common when no comps differ in garage count enough to trigger a reported adjustment.
